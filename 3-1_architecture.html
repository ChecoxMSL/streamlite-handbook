🗺️ System Architecture

This page explains how the QA Bonus Grading App connects to external services and how data flows through the system. Understanding this helps troubleshoot issues and know where data lives.

1. High-Level Data Flow

The app follows a layered architecture: the user interacts with the UI, which calls core modules, which in turn communicate with external Google services.

👤 QA Agent / Admin Browser via HTTPS
↓
🖥️ app.py + UI Panels Streamlit frontend
↓
⚙️ Core Modules Ledger, Config, History
📄 PDF Generators Reports, Certs, Banners
↓
📊 Google Sheets RAW_DB (all state)
🔍 BigQuery Call logs
📁 Google Drive PDF storage
💬 Google Chat DM dispatch

2. Google Sheets Backend (RAW_DB)

All persistent state lives in the RAW_DB spreadsheet. There are no local databases — everything is stored in Google Sheets tabs. Each environment (PROD / SANDBOX) has its own set of tabs.

💡 Sandbox Auto-Creation: Tabs marked SANDBOX are auto-created the first time you switch to SANDBOX mode. You don't need to create them manually.
📋 HR Payroll (separate workbook): The HR Sync action writes to a dedicated spreadsheet — Qa Bonus HR, tab QA Bonus Payroll — which is separate from the RAW_DB. This file is managed by HR and is not part of the app's internal state.

3. Google Drive — Folder Structure

All generated files (PDFs and PNGs) are automatically uploaded to a shared Google Drive folder. The folder structure is organized by week and office.

3.2 File Permissions & Retention

  • Files are set to "Anyone with the link" — Reader permission. This enables link preview in Google Chat.
  • Files are retained permanently on Drive. There is no automatic cleanup.
  • Local copies on the server are auto-deleted after upload (configurable via App_Config).

4. BigQuery — Call Logs

The app queries Google BigQuery to surface call recordings for QA review. When a QA agent selects dispositions to audit, the system pulls 5 call logs per disposition for the configured date range.

  • The date range for BigQuery queries is displayed in the sidebar under BQ Range.
  • QA agents can click Refresh on any disposition block to get a fresh set of 5 calls.
  • Query results are cached per session to reduce API calls.
⚠️ BigQuery Timeouts: If a query takes too long, the app shows an alert. Click the BQ Alert button in the empty state panel to retry. If the issue persists, contact the system administrator.
